# 현재 구현의 한계와 검증 범위

**검토 기준:** 2026-11-09 코드 감사. 이 문서는 특정 과거 SHA를 현재 HEAD로 고정하지 않습니다. 실제 버전은 저장소 루트의 `git rev-parse HEAD`와 같은 SHA의 CI 기록으로 확인합니다.

## 학생 호스트 관측의 보장과 한계

근거: [학생 표시](../on-client/student/extension.mjs)의 `normalizeHostObservation`, `hostReportQuality`, `hostHistoryTransition`, `hostComparison`, `hostPanel`, [호스트 수집기](../on-client/student/collect-host.mjs).

| 구분 | 현재 코드에서 수행하는 검증 | 여전히 보장하지 않는 내용 |
|---|---|---|
| 최신성 | 보고서와 개별 원천의 시간 상태를 구별합니다. 15분 경과·미래 5초 초과를 확인하며 화면은 15초 주기로 상태를 반영합니다. | 모든 OS 작업의 실제 완료 시각이나 1초 단위 상태 변화. 타이머의 화면 반영에는 최대 15초 정도 지연이 있을 수 있습니다. |
| 보고서 중복 | 정규화된 보고서 SHA-256 지문으로 동일 시각·동일 자료 재선택을 구분하고, 같은 시각 상충 자료를 비교 이력에서 제외합니다. | SHA-256 지문이 원본 서명이나 물리 PC 인증을 뜻하지 않습니다. Web Crypto 불가 시 동일 시각 자료는 보수적으로 상충 취급합니다. |
| 비교 | 비교할 두 보고서의 지문·생성 시각에 사용자의 동일 실행 환경 확인을 결속합니다. 새 파일을 선택하면 확인을 해제합니다. | 사용자 확인이 실제 동일 장치·환경의 증명임. 24시간 이동 집계 차이가 두 조회 사이 새 사건 수임. |
| OS별 적용 | macOS/Linux의 Windows 로그는 `not_applicable`을 유지하고 시간 상태는 별도로 표시합니다. | 다른 OS에 Windows System/Application 기록이 존재하거나 0건임. |
| 일부 실패 | 정상 확인된 원천만 값·단위·시각을 표시하며, 실패·상한 초과는 확인 불가로 처리합니다. | 부분 조회가 모든 네트워크·방화벽·보안 정책의 완전한 관측임. |
| 접근성 | 기본 버튼·details, 읽기 중 상태, 양쪽 화면의 갱신 후 펼침/초점 복원을 지원합니다. | 실제 모든 브라우저·보조기기에서의 완전한 동일 동작. 현장 키보드 검증은 별도입니다. |
| 방화벽 개수 | 비식별 집계에서 Windows 프로필 수, Linux 확인된 관리 도구 수, macOS Application Firewall 관측 수를 단위로 구별합니다. | 각 플랫폼의 개수를 비교해 정책 수준·안전 정도를 판단할 수 있음. |

호스트 파일은 **사용자가 직접 선택한 미서명 JSON**입니다. 보고서의 스키마·시각·구문과 지문이 맞더라도 수집기 진위, 동일 PC, 원본 변조 부재를 입증하지 않습니다. **네트워크/방화벽/Windows 경고·오류 건수는 침해나 공격 탐지 결과가 아닙니다.** 설정을 고치거나 관리자 권한을 상승시켜 수치를 확보하지 않습니다.

## 서로 다른 관측 원천

- `/api/local-pc`는 **Node 서버 실행 환경**의 CPU·메모리·앱 파일시스템 정보를 읽습니다. 파일 보고서는 별도 일반 사용자 수집기 실행 환경에서 수집한 뒤 브라우저가 수동 검증합니다. 두 환경이 같은 물리 PC라고 인증하지 않습니다.
- Node 인터페이스·주소·resolver DNS만 조회합니다. 기본 게이트웨이, 전체 라우팅, 어댑터별 DNS, 패킷은 수집하지 않습니다.
- 방화벽은 특정 OS 관리 도구의 제한된 조회입니다. Windows ActiveStore 프로필·macOS Application Firewall·Linux firewalld/UFW 조회만으로 모든 규칙이나 타사 제품의 적용을 입증할 수 없습니다.
- Windows System/Application은 각 24시간 경고(Level 3)·오류(Level 2) 건수이며 로그별 2,000건 상한이 있습니다. 성공한 실제 0, 미조회, 권한 오류, 제한 초과를 서로 다르게 처리합니다.
- CPU 시간 기반 사용률, OS free 메모리, 디스크 여유 GiB는 작업 관리자 수치·할당량·물리 호스트 전체와 다를 수 있습니다.
- 로컬 관측과 별도 설정의 **조치 모듈**은 다릅니다. 기본 관측은 읽기 전용이지만, 앱 전체가 모든 조건에서 읽기만 하는 제품이라고 주장하지 않습니다.

## 운영·시험·배포의 경계

코드에 SDP·Native 계정·AI·조치 경로가 있어도 외부 원천의 준비·계정 승인·실제 효과가 입증된 것은 아닙니다. 기본 `disconnected`, 합성 `demo`, 구성된 어댑터 `connected`를 구별하고 각 응답을 별도 검증합니다. Native 경로의 Windows 전용 조건을 macOS/Linux 전체 지원으로 확대하지 않습니다.

루트 `api/ai.js`·`api/threat-intel.js`는 로컬 앱 AI/OSV와 다르며 현재 미구현 501 경로입니다. [.github/workflows/quality.yml](../.github/workflows/quality.yml)의 CI 성공은 해당 실행기·SHA·테스트 범위에만 적용됩니다. 사용자의 PC 관측, 운영 연결, 공식 교육 평가, 공개 배포 성공은 별도 증거가 필요합니다.
