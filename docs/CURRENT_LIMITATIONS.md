# 현재 구현의 한계와 검증 범위

**검토 기준:** 2026-11-23 재귀 코드 검토. 이 문서는 특정 과거 SHA를 현재 HEAD로 고정하지 않습니다. 실제 버전은 저장소 루트의 `git rev-parse HEAD`와 같은 SHA의 CI 기록으로 확인합니다.

## 학생 호스트 관측의 보장과 한계

근거: [학생 표시](../on-client/student/extension.mjs)의 `normalizeHostObservation`, `hostReportQuality`, `hostHistoryTransition`, `hostComparison`, `hostPanel`, [호스트 수집기](../on-client/student/collect-host.mjs).

| 구분 | 현재 코드에서 수행하는 검증 | 여전히 보장하지 않는 내용 |
|---|---|---|
| 최신성 | 보고서와 개별 원천의 시간 상태를 구별합니다. 15분 경과·미래 5초 초과를 확인하며 화면은 15초 주기로 상태를 반영합니다. | 모든 OS 작업의 실제 완료 시각이나 1초 단위 상태 변화. 활성 탭에서도 다음 타이머 틱까지 지연될 수 있으며 브라우저가 타이머를 제한하면 더 늦어질 수 있습니다. |
| 보고서 중복 | 정규화된 보고서 SHA-256 지문으로 동일 시각·동일 자료 재선택을 구분하고, 같은 시각 상충 자료를 비교 이력에서 제외합니다. | SHA-256 지문이 원본 서명이나 물리 PC 인증을 뜻하지 않습니다. Web Crypto 불가 시 동일 시각 자료는 보수적으로 상충 취급합니다. |
| 비교 | 비교할 두 보고서의 지문·생성 시각에 사용자의 동일 실행 환경 확인을 결속합니다. 새 파일을 선택하면 확인을 해제합니다. | 사용자 확인이 실제 동일 장치·환경의 증명임. 24시간 이동 집계 차이가 두 조회 사이 새 사건 수임. |
| OS별 적용 | macOS/Linux의 Windows 로그는 `not_applicable`을 유지하고 시간 상태는 별도로 표시합니다. | 다른 OS에 Windows System/Application 기록이 존재하거나 0건임. |
| 일부 실패 | 정상 확인된 원천만 값·단위·시각을 표시하며, 실패·상한 초과는 확인 불가로 처리합니다. | 부분 조회가 모든 네트워크·방화벽·보안 정책의 완전한 관측임. |
| 접근성 | 기본 버튼·details, 읽기 중 상태, 양쪽 화면의 갱신 후 펼침/초점 복원을 지원합니다. | 실제 모든 브라우저·보조기기에서의 완전한 동일 동작. 현장 키보드 검증은 별도입니다. |
| 방화벽 범위 | Windows Domain/Private/Public 세 프로필이 모두 확인되고 Enabled가 명확할 때만 해당 조회 범위 완료입니다. 누락·NotConfigured는 일부 조회/확인 불가입니다. Linux는 각 도구 실패 이유를 보존합니다. | 전체 방화벽 정책·활성 프로필·타사 제품 적용의 증명. 이전 보고서의 불리언은 수집 당시 변환을 소급 검증할 수 없음. |
| 집계 내보내기 | 원천 및 항목별 최신성, Windows 집계 구간, OS, 각 플랫폼의 고유 단위를 기록합니다. 과거 수치는 과거 수치로 보존됩니다. | 원본 진위·익명성 보증·정책 수준 비교. |

호스트 파일은 **사용자가 직접 선택한 미서명 JSON**입니다. 보고서의 스키마·시각·구문과 지문이 맞더라도 수집기 진위, 동일 PC, 원본 변조 부재를 입증하지 않습니다. **네트워크/방화벽/Windows 경고·오류 건수는 침해나 공격 탐지 결과가 아닙니다.** 설정을 고치거나 관리자 권한을 상승시켜 수치를 확보하지 않습니다.

## 서로 다른 관측 원천

- `/api/local-pc`는 **Node 서버 실행 환경**의 CPU·메모리·앱 파일시스템 정보를 읽습니다. 파일 보고서는 별도 일반 사용자 수집기 실행 환경에서 수집한 뒤 브라우저가 수동 검증합니다. 두 환경이 같은 물리 PC라고 인증하지 않습니다.
- Node 인터페이스·주소·resolver DNS만 조회합니다. 기본 게이트웨이, 전체 라우팅, 어댑터별 DNS, 패킷은 수집하지 않습니다.
- 방화벽은 특정 OS 관리 도구의 제한된 조회입니다. Windows ActiveStore 프로필·macOS Application Firewall·Linux firewalld/UFW 조회만으로 모든 규칙이나 타사 제품의 적용을 입증할 수 없습니다.
- Windows System/Application은 각 24시간 경고(Level 3)·오류(Level 2) 건수이며 로그별 2,000건 상한이 있습니다. 성공한 실제 0, 미조회, 권한 오류, 제한 초과를 서로 다르게 처리합니다.
- CPU 시간 기반 사용률, OS free 메모리, 디스크 여유 GiB는 작업 관리자 수치·할당량·물리 호스트 전체와 다를 수 있습니다.
- 로컬 관측과 별도 설정의 **조치 모듈**은 다릅니다. 기본 관측은 읽기 전용이지만, 앱 전체가 모든 조건에서 읽기만 하는 제품이라고 주장하지 않습니다.

## 운영·시험·배포의 경계

코드에 SDP·Native 계정·AI·조치 경로가 있어도 외부 원천의 준비·계정 승인·실제 효과가 입증된 것은 아닙니다. 기본 `disconnected`, 합성 `demo`, 구성된 어댑터 `connected`를 구별하고 각 응답을 별도 검증합니다. Native 경로의 Windows 전용 조건을 macOS/Linux 전체 지원으로 확대하지 않습니다.

루트 `api/ai.js`·`api/threat-intel.js`는 로컬 앱 AI/OSV와 다르며 현재 미구현 501 경로입니다. [.github/workflows/quality.yml](../.github/workflows/quality.yml)의 CI 성공은 해당 실행기·SHA·테스트 범위에만 적용됩니다. 사용자의 PC 관측, 운영 연결, 공식 교육 평가, 공개 배포 성공은 별도 증거가 필요합니다.

[실행·검증](../on-client/docs/STUDENT_RUNBOOK.md) · [현재 문서 색인](README.md)

CPU는 운영체제 누적 tick의 차이를 계산하며 Windows에서 kernel time에 이미 포함되는 IRQ를 다시 합산하지 않습니다. 단조 시계와 관측 시각 사이의 차이가 과도하거나 시각 구간이 유효하지 않으면 해당 값만 확인 불가로 처리합니다. 메모리 바이트 수는 안전한 정수 범위에서만 사용합니다. 이는 작업 관리자 표시와 동일함을 보장하지 않습니다. [libuv Windows 구현](https://github.com/libuv/libuv/blob/v1.x/src/win/util.c).

실시간 PC 응답의 원천 시각은 활성 요청 구간(요청 시작 5초 전부터 수신 1초 후까지)과 최대 30초 최신성을 함께 확인합니다. 과거 자료에는 가상의 HTTP 구간을 만들어 적용하지 않습니다. 동일 생성 시각의 상충 호스트 보고서는 현재 표시·집계 저장·비교에서 제외합니다.


## XDR 후보와 정상 활동의 근거

XDR의 `record`는 정상 활동 외에도 입력이 불완전하거나 지원하는 탐지 신호가 없을 때 사용합니다. 따라서 `record`만으로 같은 주소의 다른 강한 관측을 무효화하지 않습니다. 정상 출발지·목적지 예외는 독립적으로 계산한 명시적 정상 판정과 유효한 관측 시각·주소·규칙 수준, 각 모듈에 필요한 경로·계정·에이전트·목적지 정보를 함께 확인합니다. 원문 웹 요청에 해당 모듈이 검사하는 의심 신호가 있으면 정상 활동이라는 설명만으로 예외를 만들지 않습니다. 공통 검증은 [정상 근거 검증](../xdr/normal-evidence.mjs)에 있습니다.

정상 활동의 의미는 최대 1,024자인 완전한 원문으로 판단합니다. 512자 표시 요약이 앞쪽 공백만 포함하더라도 독립적으로 확인한 정상 근거를 취소하지 않습니다. 빈 원문·길이 초과·비밀값 가림 대상은 계속 정상 예외에서 제외합니다.

이 예외는 기존 합성 경보 묶음에서 공유 주소와 정상 목적지를 보호하기 위한 후보 생성 정책입니다. `no_*_signal` 등의 무신호 결과는 정상임을 증명하지 않으며, 잘못된 관측이 다른 유효한 관측의 후보를 삭제하거나 유효 시간 구간을 연결하지 않습니다. 후보와 부가 검사는 오프라인 모의 연계이며 실제 계정·기기·원천의 신원 확인, 운영 접속 차단 또는 공식 평가 결과를 입증하지 않습니다.

## 요청 수명과 시각 변경

HTTP 제한 시간은 fetch뿐 아니라 본문 읽기와 결과 공개까지 적용합니다. 종료·취소 뒤 도착한 응답의 본문도 폐기하며, 정리 작업 자체가 완료되지 않아 원래 제한 시간이 늘어나지 않도록 합니다. 다만 운영체제의 중단 불가능한 syscall이나 이미 전송된 원격 조치 자체를 취소했다는 뜻은 아닙니다. 인증 UI의 대기 종료와 쿠키 헤더의 순서 잠금은 별도입니다. 취소를 무시하는 헤더 요청은 늦은 쿠키 충돌을 막기 위해 실제 종료까지 잠금을 유지하며, 불확실한 로그인·로그아웃을 성공으로 처리하지 않습니다.

PC 캐시는 단조 시계로 1초의 재사용 기간을 정합니다. 브라우저의 관측 시각이 뒤로 이동하면 단절 기록을 남기며, 최근 이력의 화면 표시와 내보내기는 같은 경계 규칙을 씁니다. 원천 timestamp는 계속 wall-clock 자료이므로 심한 시계 불일치는 확인 불가로 남습니다.

루트 인증 v2의 자격 수락은 할당자·인증 제공자 호출 전의 서명 시각으로부터 7일입니다. 세대 순서 증거의 브라우저 보관은 8일이며 지원하는 서버 시계 오차는 30초 이내입니다. 선택적으로 최신 쿠키만 삭제하는 경우나 임의의 서버 시계 손상까지 막는 전역 세션 철회 체계는 아닙니다. enforce 모드에서 구형 또는 서명 없는 쿠키의 자동 복원은 거부하며 명시적 재로그인이 필요합니다. [배포·호환성 조건](AUTH_COOKIE_GENERATIONS.md)을 확인합니다.


## 원천별 네트워크 관측과 완료 구간

새 v1 호스트 보고서는 선택 필드 `network.parts`로 인터페이스와 DNS의 독립적인 조회 상태·시각·사유를 기록합니다. 한 원천의 실패나 형식 오류로 다른 원천의 정상 값을 제거하지 않으며 실패한 빈 배열은 0개로 집계하지 않습니다. 구형 보고서에 없는 독립 원천 메타데이터는 만들어내지 않습니다. 보고서와 원천의 시각이 다를 때 현재 상태를 과장하지 않습니다.

Windows 이동 집계 비교는 보고서 생성 시각이 아니라 실제 집계 종료 시각에 따릅니다. 같은 집계 창을 다시 조회한 자료, 역순 집계 창, 누락된 창은 비교하지 않습니다. 기록 회전이나 보존 정책으로 사라진 이벤트까지 24시간 총건수에 포함했다고 주장하지 않습니다. 로컬 JSON의 원본·실측 여부는 미인증이며 주소·식별자 제외 집계도 시각·건수를 보존하므로 익명성 보증이 아닙니다.

SDP 전송 실패는 브라우저에서 생성한 허용된 로컬 오류 코드만 독립적으로 전달하며, 검증되지 않은 원천 모드는 계속 unknown입니다. CPU/메모리의 마지막 비교 가능한 완료 구간은 최근 10분 이력에 남은 표본의 역사적 요약이며, 현재 관측을 다시 연결하지 않습니다. Windows 설치 경로/언어, 실제 비관리자 권한, macOS 현장 검증은 아직 별도 확인 대상입니다.
