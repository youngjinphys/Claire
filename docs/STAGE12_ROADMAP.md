# Stage 12 · 차별화 가능한 다음 구현

작업 순서는 **평가 계약 준수 → 실제 서버 방어 → 외부 관측 증거 → 대응/복구** 순서입니다. 시뮬레이션 결과를 실환경 성공으로 쓰지 않습니다.

| 제안 | 필요한 실측 증거 | 차별점·한계 |
| --- | --- | --- |
| 1. XDR 인증 방어 (이번 구현) | Supabase 가명화 실패 집계와 429/403/401 실측 | 서버리스에서도 일관된 제한, WebAuthn과 독립적인 방어 계층 |
| 2. 실제 CrowdSec+Wazuh+ModSecurity 증적 교차상관 | 소스별 사건 시각·규칙 ID·서명된 수집기 ID | 단일 경보로 단정하지 않고 2개 이상 이종 출처 상호 확인. 현재 기준 밖 2개 커밋의 `homelab/`, `src/homelab-evidence.mjs`가 참고 구현 |
| 3. 의사결정 계보(Provenance) | 입력 사건 ID → 정책 revision → `decider` 결과 → 실제 API 결과 | 독립 출처 검증으로 정책 허용과 집행 성공을 구별 |
| 4. 계정 탈취/세션 재사용 탐지 | 서버 검증 세션 ID·WebAuthn credential ID의 가명화 상관관계 | 로그인 성공만으로 신뢰하지 않고 실제 재인증과 교차 검증 |
| 5. XDR 탐지 품질 표기 | 실제 정상·악성 테스트의 TP/FP/FN/TN 및 관측 창 | 정밀도·재현율·오탐 비용을 함께 보고하고 41종 달성 주장과 분리 |
| 6. 침해 후 복구 무결성 | 별도 신뢰 영역에 보존한 해시·서명·이전 버전의 단일 메모 | 실제 복구 전후 readback, 타 메모 불변 증거, 무단 복구 거부 |

현 `main`의 이전 2개 커밋 `d4e1825`, `ace8135`는 별도 백업 브랜치로 보존했습니다(브랜치 반영 후 조회). 이번 재구현에서는 **과제 격리 모드와 충돌하지 않는** 12단계 읽기 전용 점검만 선별해 가져왔습니다.
