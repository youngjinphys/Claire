# SDP 본인 기록·기기·세션 조회

[호스트](../src/engine/sdp-host.mjs)의 `readEvents`, `readDevices`, `readSessions`를 [학생 어댑터](../student/engine-adapter.mjs)가 전달하고, [서버](../src/server.mjs)가 `/api/events`, `/api/devices`, `/api/sessions`로 투영합니다. 기본 미연결에서는 성공한 빈 목록으로 대체하지 않습니다.

| 자료 | 조회 범위 | 의미의 제한 |
|---|---|---|
| 접속·XDR 기록 | 현재 본인 범위의 최근 최대 40건 | 저장된 경보. 화면을 열면서 새 공격을 탐지하는 기능이 아님 |
| 등록 기기 | 원천이 제공하는 본인 기기, 상한 100개 | OS 자원 사용률이나 물리 PC 안전의 증명 아님 |
| 세션 | 현재 검증된 연결 정보 | 전체 세션 탐색이나 다른 사용자 조회 아님 |

원천 관측은 현재 신원·프로젝트·세션과 조회 시각·범위를 검증합니다. coverage가 제공되면 전체·반환·생략 수의 정합성을 확인하며, 없는 전체 수를 추정하지 않습니다. 이벤트 발생 시각과 서버 조회 시각은 다릅니다. 알려지지 않은 과거 기기·세션 상태를 임의로 정상으로 바꾸지 않습니다.

원천의 접근 정책 `allow`는 실제 업무 앱 접속 성공과 다릅니다. `supportedActions`의 존재도 집행 권한과 효과의 증거가 아니며 별도 조치 준비·사람 확인·원천 결과 검증이 필요합니다.

**PC 파일 보고서와 별개입니다.** System/Application 경고·오류 집계와 SDP의 XDR 기록은 원천과 의미가 다릅니다. PC 조회 성공으로 SDP 상태를 변경하거나, DEMO를 원천 연결로 설명하지 않습니다.

관련: [연결 설정](SDP_HOST_CONNECTION.md), [구성도](STUDENT_ARCHITECTURE.md), [실행 확인](STUDENT_RUNBOOK.md). 실제 사용자 권한·운영 원천을 확인하지 않았다면 코드와 시험만으로 운영 성공을 기록하지 않습니다.
