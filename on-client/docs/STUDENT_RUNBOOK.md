# Claire 실행 후 확인 순서

[실행 안내](STUDENT_LAUNCH_GUIDE.md)로 같은 프로젝트의 서버 하나를 켭니다. 이 문서는 현재 기능의 확인 절차이며 과거 PASS 기록이나 공식 제출 성취를 대신하지 않습니다.

## 먼저 기록할 것

현재 커밋, Node 버전, 실행 OS, 화면 주소, 일반 권한 여부를 기록합니다. 설정 파일·토큰·원본 주소 목록은 붙여 넣지 않습니다. 과거 [릴리스 기록](STUDENT_RELEASE_RECORD.md)과 [재현 증적](STUDENT_REPRO_EVIDENCE.json)은 해당 시점의 자료로만 읽습니다.

| 순서 | 확인 | 올바른 해석 |
|---|---|---|
| 1 | `/`의 보호 현황·업무 앱·보안 기록 | 기존 화면 유지. 미연결은 오류/미연결로 표시 |
| 2 | `/dashboard.html`의 네트워크·방화벽·Windows 기록·SDP 네 카드 | 미선택 상태에 예시 수치를 넣지 않음 |
| 3 | 일반 권한 수집기로 새 보고서 생성 후 선택 | 파일 확인 시각과 OS 조회 기준 시각은 다름 |
| 4 | 성공·부분 실패·미지원 항목의 출처와 이유 | 실패는 0이 아님. macOS/Linux Windows 기록은 해당 없음 |
| 5 | CPU·메모리·디스크 한 번 측정 | 서버 실행 환경의 실측. 파일 보고서와 동일 물리 PC라고 인증하지 않음 |
| 6 | 자원 관측 시작·중지, 표본과 추이 | 사용자 시작 이후 표본만 사용. 결측을 0으로 채우지 않음 |
| 7 | 보고서 비교 확인·동일 시각 상충·상세 펼치기 | 두 보고서의 지문·생성 시각에 확인을 묶음. 이동 집계 차이는 새 사건 발생 수가 아님 |
| 8 | 비식별 집계·측정 기록 저장 | 사용자가 요청한 로컬 다운로드. 저장 완료는 브라우저에서도 확인 |
| 9 | SDP 미연결/DEMO, 선택적 AI 연결 | PC 읽기 성공과 별개의 상태 |
| 10 | 키보드·좁은 화면·종료·재실행 | 새 탭/재실행에서 이전 세션 메모리를 영구 기록으로 오해하지 않음 |

System·Application의 경고·오류 건수는 **침해나 공격 탐지 결과가 아닙니다**. 수치를 높이기 위해 오류·공격을 생성하거나 정책을 변경하는 시험을 하지 않습니다.

## 자료별 보관·시간 범위

| 자료 | 범위 | 시각·한계 |
|---|---|---|
| 파일 기반 호스트 관측 | 선택한 보고서 최대 10건, 현재 탭 메모리 | 원본 미인증. 생성 시각과 원천별 기준 시각에 대해 15분/미래 5초 판정, 화면 갱신은 최대 약 15초 지연 |
| CPU·메모리 추이 | 최근 10분·최대 120개 표본/결측 | 목표 간격 5초, 개별 값은 30초 이후 현재값으로 사용하지 않음 |
| SDP 이벤트 | 본인 범위 최근 최대 40건 | 이벤트 발생 시각과 조회 시각 분리, coverage 없는 전체 건수 추정 금지 |
| Windows 기록 | System/Application 각각 최근 24시간 | 로그별 2,000건 초과 시 정확한 총수 확인 불가 |

서버는 진행 중 자원 조회를 공유하고 짧은 캐시를 사용할 수 있습니다. 같은 관측을 다시 받았다고 새 측정 시각으로 바꾸지 않습니다. 다른 생성 시각의 파일만 비교하고 같은 시각 상충 자료는 자동 비교에서 제외합니다. 지문과 사용자의 확인은 수집 원본 인증이 아닙니다. 해결되지 않은 운영/플랫폼 경계는 [현재 한계](../../docs/CURRENT_LIMITATIONS.md)에 명시합니다.

## 조회 응답 확인

다른 일반 PowerShell 창에서 다음은 로컬 자원 조회만 수행합니다.

```powershell
Invoke-RestMethod http://127.0.0.1:5189/api/local-pc | ConvertTo-Json -Depth 8
```

각 `value`, `unit`, `source`, `measuredAt`, `status`, 실패의 `reason`을 확인합니다. JSON을 읽은 결과를 실제 Windows/SDP 전체 검증이라고 기록하지 않습니다.

## 개발 검증과 증거 수준

앱 폴더에서 `npm run check`는 두 진입 파일의 구문만, `npm test`는 로컬 시험을 검사합니다. 저장소 루트의 `node on-client/tools/dashboard-browser-smoke.mjs`는 Chrome을 이용하는 개발용 검사이며 조건을 갖춘 격리 환경에서만 실행합니다. 합성 SDP 응답, CI 머신의 OS 값, 사용자 PC 값은 각각 구분합니다.

실패 검증은 안전한 합성 파일·모의 응답으로 수행할 수 있습니다. 실제 OS 권한·방화벽·시계를 바꾸거나 공격을 재현하지 않습니다. 운영 계정·유료 AI·공식 채점·배포 성공은 코드/CI만으로 확정하지 않습니다.
