## 추가 기능과 의미

- 상단 네 카드(데스크톱 1180px 이상 한 줄), 아래 추이·보안 기록은 유지한다.
- 추이의 근거를 확인하는 측정 기록표를 추가한다. 화면은 최근 20개, 메모리는 최근 10분/최대 120개(결측 포함)이다.
- 각 센서의 원래 시각·단위·출처·실패 이유를 보존한다. 실패 시각은 성공 측정이 아니라 조회 시도로 표시한다.
- CPU는 약 400ms 구간 평균 %, 메모리는 OS total/free 차이 및 bytes/GiB, 디스크는 앱 폴더 파일시스템의 OS 보고 사용 가능 GiB이다. 할당량·네트워크 드라이브 예외는 별도다.
- 측정 시작 목표 간격은 5초이며 실패 시 수동 재개가 필요하다. CPU와 메모리의 변화 비교는 같은 연속 관측 구간의 %p 차이며 인과·침해 판정이 아니다.
- JSON 저장 버튼은 측정 자료만 사용자의 명시적 클릭으로 로컬 다운로드한다. 계정, SDP 보안 기록, 인증값, 파일 경로는 포함하지 않는다. 가상 예제 보안 기록과 PC 자원 실측은 합산하지 않는다.
- 물리 PC가 아니라 **Node 서버가 실행되는 환경**의 관측이다. WSL·컨테이너·가상머신 값이 물리 PC 전체와 같다고 보장하지 않는다.

## 실행 검증 범위

GitHub에서 읽은 다섯 원본 런타임 파일의 Git blob SHA를 로컬 사본과 대조했다. 외부 Git 복제가 차단된 작업 환경이므로 전체 저장소 체크아웃 실행이라고 주장하지 않는다.

1. 수정 전 신규 회귀검사 11개가 예상대로 실패하는 것을 확인했다.
2. 수정 후 신규 회귀검사 19개가 Linux / Node v22.16.0에서 통과했다. UI 생명주기는 실제 dashboard.mjs를 DOM·시계·HTTP 대역과 실행했다.
3. 사용자 UID 1000으로 실제 OS 측정 코드를 실행했다. 이 수치는 **검증용 Linux 환경**의 값이며 사용자 PC 실측이 아니다.
4. Chromium 144.0.7559.96에서 1440·1280px 네 카드 한 줄, 390px 모바일 페이지 넘침 없음, 시작·중지, 기록표, JSON Blob 생성 동작을 확인했다. 검사 중 JavaScript 오류는 0건이었다.
5. 이 Chromium은 관리 정책 URLBlocklist=* 때문에 localhost 탐색이 차단된다. 따라서 원본 HTML/CSS/JS의 메모리 내 DOM 테스트와 Python 루프백 HTTP 연결을 사용했다. 이 검사는 브라우저 HTTP CSP/Origin 집행, 실제 파일 다운로드 완료, 진짜 BFCache 탐색을 실증하지 않는다. 생명주기 이벤트 회귀검사는 별도이다.
6. 전체 기존 서버·루트 회귀검사는 새 최종 SHA의 GitHub Actions 결과로 확인한다. 이 문서의 로컬 결과만으로 CI 성공을 추정하지 않는다.

Windows 일반 사용자 PC, 실제 SDP/AI 계정 연결, 공식 단계 수용은 미확인이다. 과거 기록을 현재 실측으로 바꾸거나 v1.0 완료를 선언하지 않는다.

## 재현

최신 소스의 기존 `on-client` 폴더에서:

```powershell
node --version
npm run check
npm test
npm start
```

브라우저: `http://127.0.0.1:5189/dashboard.html`. 기존 세 메뉴는 `/`에 남아 있다. 일반 PowerShell 창에서 실행하며 관리자로 실행하지 않는다.

확인 순서: 미측정 상태 → 한 번 측정 → 각 센서 시각/단위 → 관측 시작/중지 → 기록표 → JSON 내용 대조 → 탭 숨김/복귀 시 자동 재개 없음 → 오류/DEMO 구분 → 종료(Ctrl+C)·재시작 후 새 기록.

```powershell
Invoke-RestMethod http://127.0.0.1:5189/api/local-pc | ConvertTo-Json -Depth 8
```

이력 통합으로 기존 main과 원격 main이 갈라질 수 있다. `git fetch origin main`은 작업 파일을 바꾸지 않는다. 미커밋/미추적 파일 또는 별도 로컬 커밋이 있으면 강제 초기화하지 말고 먼저 비교한다. `git reset --hard`, `git clean`, 자동 stash는 사용하지 않는다. HEAD가 정확히 `3447cbdec4c378cde6e9f3376263dd64cab88d84`이고 main 작업 트리가 완전히 깨끗하며 별도 로컬 커밋이 없는 경우에만 `git rebase --onto origin/main 3447cbdec4c378cde6e9f3376263dd64cab88d84 main`으로 원격 통합 이력으로 옮길 수 있다. 다른 HEAD에는 이 명령을 그대로 적용하지 않는다.
