# Claire 계정·앱 AI 연결

기본 로컬 실행과 AI 연결은 별개입니다. [실행 안내](STUDENT_LAUNCH_GUIDE.md)로 앱을 켠 뒤 기존 `/`의 보호 현황에서 연결을 확인합니다. 주소·열쇠·모델을 브라우저에 임의 입력하거나 Workbench 자격을 복사하지 않습니다.

## 화면의 순서와 의미

| 단계 | 화면에서 할 일 | 확인하는 범위 |
|---|---|---|
| 계정 연결 | 계정 연결 시작 → 안내된 확인 페이지 → 로그인 확인 완료/현재 로그인 확인 | Native 호스트가 검증한 현재 계정·프로젝트 |
| AI 앱 승인 | AI 연결 시작 → 같은 확인 번호·승인 기한 확인 → 승인했으며 연결 확인 | 앱 승인 및 로컬 자격 보관 상태 |
| 모델 목록 | 현재 API 연결 점검 | 승인된 모델 목록 접근. 실제 생성·사건 설명이 아님 |
| 사건 설명 | 보안 기록의 본인 사건에서 AI 설명 요청 | 서버가 재확인한 사건·근거·지원 조치에 결속한 설명 |
| 결과 불명 | 상태 다시 확인, 안전한 오류 정보 확인 | 취소 요청만으로 원격 승인이 철회됐다고 단정하지 않음 |

기본 실행은 필요한 운영 설정·원천 신원이 없으면 `ON_AI_PROVISIONING_PENDING` 등의 상태로 실패합니다. DEMO·합성 시험 proof와 `audienceAuthorization: test`를 운영 승인으로 표시하지 않습니다.

## Native 호스트 설정

현재 Native 계정·자격 보관 경로는 Windows 전용 검사와 helper를 사용합니다. macOS/Linux의 로컬 관제가 동작한다고 이 연결도 지원된다고 주장하지 않습니다. 담당자가 제공한 설정 파일의 실제 경로만 사용하고 내용·토큰·인증서를 프로젝트나 채팅에 넣지 않습니다.

`tools/start-alekov.ps1`의 `-NativeHostConfig`는 이 용도이며, `-SdpHostConfig`는 별도의 SDP 자격입니다. 두 설정을 함께 지정해도 두 신원이 자동으로 동일한 학생이 되지는 않습니다. 계정·프로젝트 대응은 서버 검증 대상입니다.

[Native context](../src/connection/native-context.mjs), [로그인](../src/connection/native-login.mjs), [자격 보관](../src/ai/credential-vault.mjs), [기존 준비 도구](../tools/prepare-native-host.ps1)가 소스 근거입니다. 설정을 직접 추측해 생성하거나 이 문서 개정을 이유로 운영 등록부를 변경하지 않습니다.

## 직접 서버 설정은 별도 개발 경로

`ON_AI_BASE_URL`, `ON_AI_APP_KEY`, `ON_AI_MODEL`을 사용하는 코드가 있지만 값의 존재만으로 현재 계정·앱 권한을 검증하지 못합니다. 서버 소유의 신원 공급·승인 verifier가 필요합니다. Native 경로와 임의 혼용하지 않습니다. 공급사 원본 키나 Workbench 키를 대체 자격으로 넣지 않습니다.

AI는 유한한 사건 설명·학습지원 계약을 따르며 원격 명령을 실행하지 않습니다. 임의 기본 모델이나 목록 첫 모델을 선택하지 않습니다. 지원되지 않는 모델·근거·조치와 검증할 수 없는 응답은 성공으로 사용하지 않습니다.

오류별 다음 행동은 [문제 해결](CONNECTION_TROUBLESHOOT.md), 정확한 입력·출력·권한 경계는 [AI 모듈](../src/ai/README.md)에 모았습니다. 이 저장소로 외부 운영 발급 상태·유료 모델 성공·공식 채점을 확정하지 않습니다.
