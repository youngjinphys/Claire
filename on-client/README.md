# Claire 로컬 앱 0.2.11

기존 프로젝트의 이 폴더에서 실행합니다. 단계마다 새 폴더를 만들거나 이전 제출물을 지울 필요가 없습니다. 내부 `alekov` 식별자는 프로토콜 호환용입니다.

```sh
node --version
npm run check
npm start
```

Node 지원 선언: `>=22.15 <23 || >=23.5 <25 || >=26 <27`. CI 기준: 24.19.0. 외부 npm 의존성 없음. 기본 주소는 `http://127.0.0.1:5189/`, 통합 관제는 `/dashboard.html`, 종료는 Ctrl+C입니다. `.env.example`은 참고 자료이고 시작 시 자동 로드되지 않습니다.

| 화면/자료 | 실제 동작 | 한계 |
|---|---|---|
| 기존 `/` | 보호 현황·업무 앱·보안 기록, 학생 렌더러, 조건부 AI·조치·패키지 조회 | 기본 실행은 SDP 미연결 |

| `npm run demo` | 가상 SDP 자료 | PC 실측·운영 연결·공식 통과로 보고하지 않음 |

Windows System·Application의 최근 24시간 경고·오류 건수는 **침해나 공격 탐지 결과가 아닙니다**. macOS/Linux에서는 해당 없음이며, 권한·도구·시간 초과는 확인 불가입니다. 수집기는 방화벽·보안 설정을 바꾸거나 권한을 상승시키지 않습니다.

`npm run check`는 학생 확장과 서버 두 파일의 구문 검사입니다. `npm test`는 이 폴더의 테스트를 실행하며 운영 계정 연결을 대신하지 않습니다. 런타임 기능이 있다는 사실, CI 성공, 실제 PC 관측, 공식 평가를 분리해 기록합니다.


**관측 실패·최신성 표시:** PC 센서 조회가 모두 실패하면 `측정 실패 · 다시 측정 필요`, 일부 센서만 성공하면 `일부 측정 실패`, 기존 표본의 경과 시간이 30초를 초과하면 `측정값 오래됨`을 표시합니다. 조회 실패나 SDP 미연결은 수치 0이나 정상 판정으로 바꾸지 않습니다. 학생 보고서의 상세 영역은 최신성 갱신 후 열린 상태·키보드 초점 복원 경로를 사용합니다. Windows 프로필 일부 누락/미설정과 Linux 도구별 조회 실패는 확인 가능한 범위만 표시합니다. 집계 JSON에는 원천별 최신성과 Windows 집계 구간을 포함합니다.

**실시간 응답의 시각 검증:** 새 요청과 측정 시각을 대조합니다(요청 시작 5초 전부터 응답 완료 1초 후까지의 허용 범위, 최대 30초 최신성). 이 범위에 맞지 않는 개별 센서값은 제외하며 나머지 센서값은 유지합니다. 전체 실패 시 성공한 실측값이 없음을 표시합니다. SDP 기록의 과거·시각 불일치 표시와 재조회 중 기존 DEMO 표시는 같은 원천 정보를 유지합니다. 과거 기록은 현재 상태 판정으로 사용하지 않습니다.

### 연속 관측 구간의 표본 최대값 (2026-11-22)

기존 CPU·메모리 비교 추이에, 첫 표본과 마지막 표본의 변화(%p)뿐 아니라 **같은 연속 관측 구간에서 실제로 수집한 최대값(%)**도 함께 표시합니다. 변화 폭이 0%p여도 중간에 관측된 사용률 증가를 감출 수 없도록 하는 보완입니다. 빈 구간·센서 실패·15초 초과 간격은 이전 구간을 끊으며, 새 구간의 최대값에 과거 구간 자료를 섞지 않습니다. 표본 사이의 미관측 피크를 추정하거나 보안 이상을 판정하지 않습니다.


시계가 뒤로 이동한 관측은 연속 추세에서 분리합니다. 단조 시계로 캐시 재사용 기간을 정하므로 PC 시계 조정이 캐시를 무기한 연장하지 않습니다. 표시와 JSON은 같은 보관 경계를 사용합니다. HTTP 연결과 본문 처리는 기한·취소 후 결과를 공개하지 않으며, 화면 로딩이나 저장 요청 실패는 사용자가 다시 시도할 수 있는 상태로 남깁니다.

### 관측 근거 개선 (2026-11-24)

- 네트워크 인터페이스와 Node DNS resolver의 성공·실패·기준 시각을 독립적으로 유지합니다. 읽기 실패는 집계 JSON에서도 null이며 기존 v1 보고서는 계속 지원합니다.
- Windows 비교는 보고서 생성 시각이 아닌 실제 집계 종료 시각을 사용합니다. 동일 집계 창의 재조회 및 역순 창은 추이로 비교하지 않습니다. 로그 보존 범위 내 건수이며 침해 탐지 결과가 아닙니다.
- SDP HTTP 전송·크기·형식 오류는 원천 모드 미확인과 분리해 표시합니다. 원격 응답에 포함된 임의 오류 문자열을 로컬 오류로 승격하지 않습니다.
- 관측 중지·실패 뒤에도 최근 10분 내 마지막 비교 가능한 완료 구간의 분석을 과거 자료로 표시합니다. 다음 관측과 연결하거나 이전 최대값을 현재 피크에 섞지 않습니다.
- 파일 원본과 실제 수집 여부는 미인증입니다. 주소·식별자 제외 집계도 시각·건수를 포함하므로 완전한 익명성을 보장하지 않습니다. 원본 임시 보고서의 개인정보와 보관·정리는 [호스트 수집 안내](student/HOST_OBSERVATION.md)를 확인하세요.

일반 조회와 화면 모델만 검증하려면 `node --test test/host-collection.test.mjs test/student-host-view.test.mjs test/dashboard-regression.test.mjs test/dashboard-resilience.test.mjs`를 실행합니다. 전체 CI의 포장/공격 모의 범위를 대신하지 않으며 실제 사용자 PC나 운영 연결을 검증했다는 뜻이 아닙니다.

### 관측 재개와 화면 갱신 (2026-11-28)

- 관측 중지 직후 다시 시작하여 서버의 같은 캐시 응답을 받으면 `이전 PC 측정값 재확인 · 새 표본 없음`으로 안내합니다. 표본 수와 JSON 기록을 중복으로 늘리지 않으며, 재개 구간의 변화량은 새로 수집한 두 표본부터 계산합니다. 실제 시계가 뒤로 바뀌면 기존처럼 구간을 분리합니다.
- 학생 보고서의 상세 펼침과 키보드 초점은 부분 갱신 및 기본 화면의 학생 패널 전체 교체에서 유지합니다. 사용자가 다른 컨트롤로 이동한 뒤에는 예약된 복원이 초점을 가져오지 않습니다.
- 최신성 갱신은 네트워크 카드의 집계 상태뿐 아니라 인터페이스·DNS 원천의 개별 시각도 확인합니다. 한 원천이 먼저 오래된 상태가 되어도 나머지 원천의 표시가 계속 갱신됩니다.
- SDP 기록 재조회 중에도 종류 필터는 이전에 받은 기록에 즉시 적용됩니다. `조회 중`, 이전 원천 및 DEMO 표시는 유지하며, 필터 변경으로 추가 조회를 보내지 않습니다.

위 동작의 선택 검사는 `node --test test/dashboard-regression.test.mjs test/dashboard-lifecycle.test.mjs test/dashboard-resilience.test.mjs test/student-host-view.test.mjs`입니다. 실제 브라우저에서 기본 화면의 상세 펼침·Tab 이동과 대시보드의 중지→재개·재조회 중 필터를 확인하는 절차는 별도입니다.
